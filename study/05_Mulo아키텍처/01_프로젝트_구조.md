## 계층별 역할

### data/models/ — 데이터 구조 정의

- 순수 데이터만 담는다.
- 비즈니스 로직 없음.
- freezed로 자동 생성.

```dart
// C#의 record class와 동일
@freezed
class Moment with _$Moment {
  const factory Moment({
    required String id,
    required String caption,
    required double startSec,
    required double endSec,
  }) = _Moment;
}
```

### data/repositories/ — API 통신

- HTTP 호출만 담당.
- Widget도 ViewModel도 Dio를 직접 쓰지 않음.

```dart
class MomentRepository {
  Future<List<Moment>> getFeed(String groupId) async { ... }
  Future<Moment> createMoment(...) async { ... }
}
```

### data/services/ — 외부 SDK 래핑

- Spotify SDK, YouTube API 등 외부 라이브러리를 단순하게 래핑.
- ViewModel이 SDK를 직접 호출하지 않도록 중간 레이어.

### presentation/**/viewmodel.dart — ViewModel

- Repository / Service 호출.
- state 변경.
- UI 코드 없음.

### presentation/**/screen.dart — View

- ViewModel의 state를 watch해서 화면 렌더링.
- 비즈니스 로직 없음.
- 사용자 액션 → ViewModel 메서드 호출.

## 새 화면 만들 때 세트

화면 하나를 추가할 때 항상 이 3개를 같이 만든다.

```
presentation/
└── 새기능/
    ├── 새기능_screen.dart       ← UI
    ├── 새기능_viewmodel.dart    ← 상태 관리
    └── (필요시) data/repositories/새기능_repository.dart  ← API
```

## pubspec.yaml — 패키지 관리

C#의 `.csproj`나 `packages.config`와 같은 역할.

```yaml
dependencies:
  flutter_riverpod: ^2.6.1   # 상태관리
  go_router: ^14.8.1          # 라우팅
  dio: ^5.8.0                 # HTTP
  freezed_annotation: ^2.4.4  # Model 자동생성
  ...

dev_dependencies:
  build_runner: ^2.4.15       # 코드 자동생성 실행기
  freezed: ^2.5.8             # freezed 코드 생성기
```

패키지 추가 후 반드시:
```
flutter pub get
```

## 자주 쓰는 명령어

```bash
flutter pub get          # 패키지 설치 (npm install과 같음)
flutter run              # 앱 실행
flutter run -d chrome    # 웹으로 실행
flutter analyze          # 코드 분석 (에러 찾기)
flutter clean            # 빌드 캐시 삭제 (문제 생길 때)

# freezed 코드 자동생성 (Model 클래스 만들 때)
dart run build_runner build
```
